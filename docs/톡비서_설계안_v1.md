## A. 캐시 구조 — 추천안

1. **왜 캐시가 반드시 필요한가 [확정]**: 이카운트는 재고·품목 **목록조회를 10분에 1회**만 허용합니다(인계서 2-5).
   손님이 5분 사이에 열 명 물어보면 실시간 조회로는 전부 막힙니다. 게다가 카카오 챗봇은 **5초 안에** 답해야 합니다.
2. **추천 구조**: 서버(Render)가 스스로 시계를 보고 미리 받아 두고, 손님 질문에는 **받아 둔 자료로 즉시** 답합니다.
   | 무엇 | 받는 주기 | 하루 호출수 | 이카운트 한도 |
   |---|---|---|---|
   | 재고(창고별재고현황 목록) | 10분마다 | 144회 | 1일 5,000건 [확정] |
   | 가격·품목명(품목조회 목록) | 1시간마다 | 24회 | 〃 |
   가격은 재고만큼 자주 바뀌지 않으므로 1시간이면 충분하다고 봅니다 **[추론 80%]**. 10분으로 당겨도 한도에는 여유가 있습니다.
3. **보관 위치**: 서버 메모리(품목 2,195개 기준 몇 MB 수준, 부담 없음). Render가 재시작되면 캐시가 비므로,
   **서버가 켜질 때 한 번 즉시 받아 채웁니다.** 이번에 넣은 `ecountLimits.js`가 이 캐시와 10분 간격을 이미 지켜 줍니다.
4. **답변에 시각 표시**: "2026-09-13 15시 40분 기준 재고 12개" 처럼 **언제 자료인지 항상 붙입니다.**
   손님에게 10분 전 숫자를 실시간인 척 말하지 않기 위해서입니다.
5. **딱 지금 값이 필요할 때**: 주문 직전 확인 등은 단건조회 API(1초 1회)로 그 품목만 실시간 조회합니다.

## B. 품목 찾기 방식 — 추천안

1. **문제 [확정]**: 손님은 품목코드를 모르고 "월넛 4인 식탁"처럼 말합니다. 현재 이카운트 품목 2,195개는
   코드·색상 표기가 제각각이라(9-12 분석) 이름만으로 맞히기 어렵습니다 **[추론 70%]**.
2. **추천: 3단계로 좁힙니다.**
   - 1단계 **별칭표**: 자주 묻는 상위 50품목만 "손님 말 → 품목코드" 표(구글 시트 1장)로 만들어 시작.
     사장님·직원이 시트에 한 줄 추가하면 바로 반영되게 합니다. 가장 빨리 정확해지는 방법입니다.
   - 2단계 **부분일치 검색**: 품목명·규격·바코드·추가문자항목(CONT1~6)에서 찾되, 띄어쓰기·괄호를 없애고 비교.
   - 3단계 **되묻기**: 후보가 여럿이면 버튼 3개로 "이 중 어느 것인가요?" 되묻습니다.
     **틀린 답을 자신 있게 하는 것보다 되묻는 쪽이 안전합니다.**
3. 진행 중인 품목코드 13자 정비가 끝나면 2단계 정확도가 크게 올라갑니다.

## C. 카카오 오픈빌더 스킬 응답 규격

1. **[확정, 출처: 카카오 도움말 검색 결과 요약]** 스킬 타임아웃은 **5초 고정**. 응답은 `version` / `template` / `context` / `data`
   4가지로 구성되고, `version`을 안 쓰면 1.0으로 인식됩니다.
2. **[추론 85%, 클로드 일반 지식]** 실제 응답 형태는 아래와 같습니다. 원문 확인 전까지는 확정이 아닙니다.
   ```json
   { "version": "2.0",
     "template": { "outputs": [ { "simpleText": { "text": "○○ 의자\n판매가 89,000원(부가세 별도)\n재고 12개\n2026-09-13 15:40 기준" } } ],
       "quickReplies": [ { "label": "다른 색상", "action": "message", "messageText": "다른 색상" } ] } }
   ```
3. **확인 필요 — 이 세션에서는 못 했습니다.** `i.kakao.com`과 `kakaobusiness.gitbook.io`가 이 작업 환경의 네트워크 정책으로
   차단되어 원문을 열지 못했습니다(2026-09-13 확인). 우회 방법 3가지:
   - ① 코워크(브라우저 사용 가능)에게 `i.kakao.com/docs/skill-response-format` 원문 정리를 요청 — 가장 빠름
   - ② 사장님 크롬에서 그 페이지를 열어 두고 화면을 보여 주시기
   - ③ 제미나이/퍼플렉시티에 "카카오 i 오픈빌더 스킬 응답 JSON 최신 규격" 조회 요청
4. **선행 준비 [추론 80%]**: 카카오 비즈니스 채널(사업자 인증) → 오픈빌더 챗봇 생성·채널 연결(승인 절차 있음) →
   스킬 서버 HTTPS 주소 등록(Render 주소 사용 가능).

## D. 사장님이 정해 주실 4가지 (제 추천을 먼저 답니다 — 승인/반려만 하시면 됩니다)

1. **어느 단가를 보여줄까** → 추천: 채널 공개 답변은 **기본 출고단가(OUT_PRICE)만**. 거래처 등급가(단가A~J)는 채널에서 숨기고,
   등급가는 나중에 "직원용 톡봇"에서만. 이유: 누가 보는지 모르는 공개 채널에서 등급가가 새면 거래처 간 가격 분쟁이 납니다.
   원가(IN_PRICE)는 어떤 경우에도 노출 금지 [확정, 인계서 6-4].
2. **재고를 어떻게 보여줄까** → 추천: **남양주창고(001) 기준 한 줄**. 004 미확인재고·005 하자제품·시험창고(test5, test6)는 제외.
   이유: 합계로 보여주면 팔 수 없는 재고까지 숫자에 들어가 약속을 못 지키게 됩니다.
3. **못 답하는 질문은 누구에게** → 직원 이름·번호 1명(또는 대표번호) 지정해 주시면 "담당자에게 연결" 버튼으로 넘깁니다.
4. **영업시간 외 문구** → 추천: "지금은 영업시간이 아닙니다(평일 09~18시). 남겨 주시면 다음 영업일에 연락드립니다."

## E. 구현 순서 제안 (승인 후)

1. 1단계: 캐시 + 품목 찾기 + 답변 문구를 **웹 화면에서 먼저 시험**(카카오 연결 없이). 사장님이 직접 질문을 넣어 보고 답을 확인.
2. 2단계: 카카오 규격 확정 후 스킬 엔드포인트(`/kakao/skill`) 추가.
3. 3단계: 채널 연결·승인, 상위 50품목 별칭표 채우기, 시험 운영.
