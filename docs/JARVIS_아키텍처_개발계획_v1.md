## A. 현재 상태 진단 — 자비스 스펙 vs 이미 만들어진 것

━━━━━━━━━━━━━━━━━━━━━━━━━━━

이 저장소(ecount-mcp)에는 이미 "AI 회의실" MVP가 부분적으로 구현되어 있습니다 (2026-09-03~06 작업, 커밋 이력 확인). 자비스 스펙과 대조한 결과는 아래와 같습니다.

**A-1. 이미 스펙과 일치하는 부분**
- Provider Adapter 구조: `providers.js`가 스펙 08번 문서의 `AIProvider` 인터페이스와 사실상 동일한 방식으로 구현되어 있음. 클로드·제미나이·딥시크·오픈AI(+그록)가 이미 연결되어 있고, 새 AI는 함수 하나 + 환경변수만 추가하면 자동 참석 — 스펙이 요구하는 "10개, 100개로 늘어나도 구조를 안 뜯어고치는" 조건을 이미 충족.
- Secret 관리: API 키는 전부 Render 환경변수. 코드/Git에 하드코딩 없음 — 스펙 05번 문서 요구사항 충족.
- 웹 기반: Express 서버가 Render에 배포되어 브라우저로 어디서나 접속 가능 — 스펙이 요구하는 "집/회사 PC 어디서나 같은 접속" 조건은 이미 충족 (단, 로그인은 없음 — 아래 A-2 참고).
- 1차 독립답변: `runRound()`가 참석자 전원에게 "같은 질문"을 동시에 물어보는 구조는 이미 있음.
- 이식성: 표준 Node `fetch`만 사용, 렌더 전용 기능 없음 — 나중에 Cloud Run으로 옮기라는 사장님의 기존 지시(9/6 회의록)를 이미 만족.

**A-2. 스펙에는 있지만 아직 없는 것 (이번에 채워야 할 부분)**
1. **Google 로그인 없음** — 지금은 URL만 알면 누구나 `/meeting` 접속 가능. 스펙은 Google 계정 로그인을 전제로 함.
2. **Google Drive 연동 없음** — MASTER 지침·현재 결정사항을 자동으로 읽어오는 기능 없음. 회의 종료 후에도 Drive(자비스미팅테이블)에 자동 저장되지 않음. 지금은 요약만 웹훅(Make)으로 시트에 보내는 "설정하면 되는" 상태이고, 실제 시트/시나리오는 아직 안 만들어짐.
3. **회의 상태가 서버 메모리에만 있음** — 서버 재시작(무료 요금제 슬립 포함) 시 진행중이던 회의가 통째로 사라짐. 스펙은 "회의별 고유 ID로 영구 저장"을 요구.
4. **비교 엔진(Comparison Engine) 없음** — 지금은 각 AI가 순서대로 말만 함. "공통 의견/불일치/근거/가정/불확실성/소수반론"을 구조화해서 뽑아내는 기능은 없음.
5. **참여 AI를 회의마다 선택하는 기능 없음** — 지금은 설정된 AI 전원이 무조건 참석. 스펙은 "참여 AI 체크박스"를 요구.
6. **실무자 검토 / 대표 승인 상태 필드 없음** — 지금은 대화만 쌓이고 "검토중/수정요청/보류/승인/기각" 같은 상태 관리가 없음.
7. **Context Snapshot 기록 없음** — 이번 회의에 어떤 자료(파일ID·수정시각)를 근거로 썼는지 기록하는 기능 없음.

**A-3. 판단이 필요한 충돌 지점**
스펙 08번 문서는 "Apps Script MVP vs Cloud Run MVP를 비교하고 추천하라"고 요구합니다. 그런데 이미 Render(Node/Express) 위에 상당 부분이 동작 중입니다. 이 셋 중 하나를 고르는 문제이므로 — 사장님 지시("판단 필요한 결정은 먼저 물어볼 것")에 따라 아래 B, D에서 제 추천과 이유를 먼저 제시하고 승인을 받겠습니다.

## B. 권장 아키텍처 (마스터프롬프트가 요구한 10개 산출물)

━━━━━━━━━━━━━━━━━━━━━━━━━━━

**B-1. 추천 기술스택**
기존 Render(Node/Express) 유지를 추천합니다. (확신 80%, 근거: 이미 이식 가능하게 짜여 있고, 상당 기능이 동작 중이며, Apps Script로 새로 짜면 지금까지 작업을 버리고 다시 만들어야 함 — 실행시간 제한(6분)·병렬호출 제어가 Apps Script는 더 불편함.) Cloud Run 전환은 "지금 당장"이 아니라 "필요해지면"(무료 슬립이 실제로 문제될 때) 옮기는 것으로 미뤄도, 코드가 이미 이식 가능하므로 손해가 없습니다.

**B-2. 전체 구조도**
```
브라우저 (Google 로그인)
  ↓
Web UI (public/meeting.html — 확장 필요)
  ↓
JARVIS API (server.js — 이미 있음)
  ├─ Context Builder ─── Google Drive (신규, 서비스 계정)
  ├─ Provider Router ─── providers.js (이미 있음: Claude/Gemini/DeepSeek/OpenAI/Groq)
  ├─ Comparison Engine (신규)
  ├─ Meeting State ───── 지금: 서버 메모리 → 앞으로: Drive에 회의별 파일로 영속화
  └─ Drive Archive Writer (신규) ─── 자비스미팅테이블/02_AI_회의실
```

**B-3. Google 인증 방식 (제 추천)**
Google OAuth 로그인을 붙이되, **허용된 이메일만** 접속 가능한 화이트리스트 방식을 추천합니다 (구글 앱 심사 없이 "테스트 모드"로 시작 가능, 승인된 사람 외 원천 차단). 화이트리스트는 코드가 아니라 환경변수나 별도 설정파일로 관리.

**B-4. Google Drive 접근 방식 (제 추천 — 판단 필요, D-2 참고)**
개별 직원마다 Drive 권한 동의를 받는 방식(OAuth per-user) 대신, **서버용 서비스 계정(Service Account)** 하나에 "자비스미팅테이블" 폴더만 공유 권한을 주는 방식을 추천합니다. 이유: 로그인은 "누가 회의를 열었는지 식별"용으로만 쓰고, Drive 읽기/쓰기는 서버가 서비스 계정으로 대신 처리 — 매번 직원 개인 동의창을 띄울 필요가 없어 운영이 단순해짐 (확신 75%, 사장님 승인 필요 사안).

**B-5. Secret 관리 방식**
기존 원칙 그대로 유지: Render 환경변수. 서비스 계정 키(JSON)도 Render의 Secret 환경변수로 저장 — Git/코드에 절대 포함 안 함.

**B-6. Provider Adapter 설계**
이미 구현됨 (`providers.js`). 추가 작업 불필요 — 새 AI 추가 시 함수+환경변수만.

**B-7. 데이터 모델 (신규 필요)**
회의 1건 = 다음 항목을 가진 파일(JSON 또는 Markdown)로 Drive에 저장:
`meetingId · topic · 참여 AI 목록 · context_snapshot(사용한 파일ID·수정시각) · AI별 원문답변 · 비교결과(공통/불일치/근거/가정/불확실성) · 재검토결과 · 실무자메모 · 대표승인상태(검토중/수정요청/보류/승인/기각) · 생성/수정시각`

**B-8. MVP 기능범위**
포함: Google 로그인(화이트리스트) · 참여 AI 선택 · 1차 독립답변(이미 있음) · 비교 엔진 · 재검증 라운드(이미 있음, 암행어사 기능으로 유사 구현됨) · 실무자 메모 입력 · 대표 승인상태 저장 · Drive 자동 기록.
제외(스펙 08번 문서 그대로, 이번 단계 안 함): vector DB, 자동 웹검색, 자동승인, 업무실행 에이전트, 복잡한 조직권한, 카톡/슬랙 자동발송, 이카운트 자동쓰기, 노션 자동동기화.

**B-9. 비용/쿼터/확장**
Render 무료 요금제 계속 사용(기존 결정사항 유지, 필요시 유료 전환은 이미 사장님 승인된 방향). Google Drive API 무료 쿼터로 이 사용량은 충분(하루 수십 건 수준). Google 로그인 앱은 "테스트 모드"로 시작하면 별도 심사·비용 없음.

## C. 개발 단계 (승인 후 순서)

## D. 사장님 승인이 필요한 판단사항 (제 추천 포함, 번호로 답해주시면 됩니다)

━━━━━━━━━━━━━━━━━━━━━━━━━━━

**D-1.** 기술스택: 기존 Render(Node/Express) 유지, Cloud Run 전환은 나중으로 미룸 — 제 추천입니다 (이유: B-1). 승인/반려/보류?

**D-2.** Drive 접근 방식: 서비스 계정 방식(직원 개인 동의 불필요) — 제 추천입니다 (이유: B-4). 승인/반려/보류?

**D-3.** 회의 기록 저장 방식: Drive API로 서버가 직접 파일 저장(Make 시나리오 불필요, 더 단순함) — 제 추천입니다. 기존에 구상하셨던 "구글시트 2개 + Make 경유" 방식(9/6 회의록)과는 다른 방향이라 반드시 여쭤봅니다. 승인/반려/보류?

**D-4.** 로그인 허용 대상: 대표님만? 아니면 부장급 이상도 포함? 허용할 이메일 목록을 알려주셔야 화이트리스트를 만들 수 있습니다.

승인 주시면 1단계부터 시작하겠습니다.
